## 部署实战踩坑（重要，复用）
- **最终成功上线**：2026-09-23 用有效 Token 经 wrangler 直传部署，项目 `brand-blog` 已建，生产地址 https://brand-blog.pages.dev （部署预览 https://<hash>.brand-blog.pages.dev）。上传 28 文件，_headers/_redirects 已同步。
- **坑1 代理**：沙箱存在本地代理 127.0.0.1:10199，wrangler/curl 默认走代理会改写 Authorization 头导致 `9109 Invalid access token`。解决办法：运行前清空 `$env:HTTP_PROXY/HTTPS_PROXY/ALL_PROXY=""` 并设 `NO_PROXY="*"`（或直接 `curl --noproxy "*"`）。deploy.ps1 已内置此处理。
- **坑2 Token 生效时间**：Cloudflare 自定义令牌的「开始时间」若误设成未来日期（如 Oct 24），verify 会返回 `not_before` 在未来且 10002 报错，今天用不了。必须「开始时间=今天」。
- **坑3 别从截图读 Token**：Token 含大量形近字符（l/I/1、O/0），从截图 OCR 极易读错（曾把 `loGDyj` 误读成 `IoGDyj`）。务必让用户用「复制」按钮粘贴成纯文本。
- **坑4 wrangler 4.x 创建项目**：`pages deploy --project-name X` 不会自动建项目，需先 `wrangler pages project create X --production-branch main`（已存在时报错可忽略），再 deploy。
- Token 仅显示一次且 TTL 用户设为 1 天，部署完建议用户在后台 Revoke。
